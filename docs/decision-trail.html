What the trader saw, what it decided, and what is kept

Every time the trader wakes up it reads data through tools, sometimes decides something, and leaves a trail of records behind. This page names each record, shows how they point to each other, and says how long each one lives.

The one rule

Kept for good

Decisions, orders and fills, plus everything a decision points to as its reason.

Temporary

Everything else the trader looked at: scan pages, routine checks, snapshots nobody acted on. Deleted after a set number of days.

How the records point to each other

One turn on 12 November: the trader scans the watchlist, reads a second page, plans a KO entry, writes a review, and buys.

Tool call record

90 days

One tool the agent used: what it asked for and what came back. Also called a receipt.

id
<turn>:<round>:<index>, e.g. 16b76fb4-…:134:0 = round 134, first call
holds
requestId, role, name, input, result, start and finish time
lives in
db/days/<date>/tool-calls.jsonl, the day the turn started (US Eastern)

Snapshot

2 days

The full result of a big tool call, frozen so it can be read page by page without prices moving between pages.

id
the first record's id (the snapshotId)
holds
the whole scan: every stock's price, signals, RSI, ATR, risk check; scan time; warnings
lives in
db/days/<date>/snapshots/<id>.json; the record keeps a pointer { kind, file, bytes }

Page

not stored

What the trader actually receives: a slice of the snapshot. It is the result of each record.

holds
rows, snapshotId, offset, total, nextOffset
links
a later page's record has input.snapshotId pointing back to the first record

One KO buy, from start to a year later

  1. Nov 12 15:00
    The trader wakes. That is a turn.
  2. 15:00
    It calls get_watchlist_scan. A tool call record is written, the full scan is saved as a snapshot file, and the trader gets page 1.
  3. 15:01
    It reads pages 2, 3 and on. Each is a new record pointing back to the first one.
  4. 15:01
    It runs get_entry_plan for KO: another record, the entry plan.
  5. 15:02
    It writes a review: "KO: buy, because …", naming the scan and the plan.
  6. 15:02
    It buys. A decision goes in the journal, pointing to the scan, plan and review. An order goes to the broker; a fill comes back.
  7. Nov 14
    The cleanup deletes that day's snapshot files. It first sees the KO decision cites the scan, so the scan's record and snapshot are copied to evidence.
  8. Feb 10
    90 days on, the cleanup deletes that day's records. The KO plan and review are copied to evidence first. Pages nobody acted on and routine checks are gone.
  9. Nov 2027
    You ask "why did it buy KO?". The decision is still in the journal, and everything it points to is in evidence/.

The folder

db/
├── journal.jsonl            decisions and reasons
├── orders.jsonl             what was sent to the broker
├── fills.jsonl              what the broker executed
├── requests.jsonl           turns
├── tool-calls.jsonl         old single file: read when needed, never cleaned
├── state.json               app state, incl. retention settings
├── days/
│   ├── first-day.json       the day this layout began
│   └── 2026-11-12/
│       ├── tool-calls.jsonl     that day's records, 90 days
│       └── snapshots/<id>.json  frozen scans, 2 days
└── evidence/
    ├── <id>.json            a record a decision relies on, with its snapshot
    └── index.jsonl          so kept copies still show in lists

Most snapshots never become evidence: the trader looks, decides nothing, and the snapshot goes after two days.
